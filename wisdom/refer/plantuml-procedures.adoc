= PlantUML generation procedures reference
:description: Complete reference for the plantuml.scm Steel library
:icons: font

The `plantuml.scm` library lives at `script/plantuml.scm`.
Load it with:

[source,scheme]
----
(require "plantuml.scm")          ; if script/ is on the load path (-L script)
; or
(require "script/plantuml.scm")
----

The `syster/base` functions (`syster/parse-file`, `hir-symbol/*`, etc.) and the
`hbs/*` functions are registered automatically — no `require` is needed for them.

On load, `plantuml.scm` creates a shared Handlebars registry `*hbs*` and registers
the five templates from `*templates-dir*` (default: `"script/templates"`).
All diagram generators call `(hbs/render *hbs* ...)` internally.

All procedures that generate diagrams accept an optional `opts` hash as their
last argument.
Omitting it uses the defaults shown in the tables below.

== Diagram generators

=== `(generate-bdd symbols [opts])` → string

Generate a Block Definition Diagram from a list of `HirSymbol` values.

Selects `PartDefinition`, `PortDefinition`, and `AttributeDefinition` symbols.
Renders each definition as a PlantUML `class` with the `<<block>>` stereotype.
Derives composition lines from `PartUsage` children.
Derives inheritance lines from `Specializes` relationships.

[source,scheme]
----
(define puml-text (generate-bdd (syster/file-symbols model)))
----

[cols="2,1,1,3"]
|===
| Key | Type | Default | Effect

| `"title"` | string | `""` | Add a `title` directive
| `"theme"` | string | `"default"` | PlantUML `!theme` directive
|===

Output structure is controlled by `script/templates/bdd.hbs`.

=== `(generate-ibd parent-sym symbols [opts])` → string

Generate an Internal Block Diagram showing the interior of `parent-sym`.

Selects `PartUsage` and `PortUsage` children of `parent-sym`.
Renders each part as a component.
Selects `ConnectionUsage` symbols for connector lines.

[source,scheme]
----
(define vs   (syster/find-by-name symbols "VehicleSystem"))
(define puml (generate-ibd vs symbols))
----

[cols="2,1,1,3"]
|===
| Key | Type | Default | Effect

| `"title"` | string | `""` | Diagram title
| `"direction"` | string | `"left to right direction"` | Diagram flow direction
|===

Output structure is controlled by `script/templates/ibd.hbs`.

=== `(generate-package-diagram symbols [opts])` → string

Generate a package diagram showing packages and their contents.

Selects `Package` symbols and their direct children.
Output structure is controlled by `script/templates/package.hbs`.

[source,scheme]
----
(define puml (generate-package-diagram (syster/file-symbols model)))
----

Accepts `"title"` and `"theme"` options.

=== `(generate-state-machine sym symbols [opts])` → string

Generate a state machine diagram for a `StateDefinition` symbol.

Selects `StateUsage` and `TransitionUsage` children of `sym`.
Output structure is controlled by `script/templates/state-machine.hbs`.

[source,scheme]
----
(define op-state (syster/find-by-name symbols "OperationalState"))
(define puml     (generate-state-machine op-state symbols))
----

Accepts a `"title"` option; the title defaults to `"<name> State Machine"`.

=== `(generate-viewpoints-diagram symbols [opts])` → string

Generate a diagram showing viewpoints, view definitions, renderings, and their
instantiation and rendering relationships.

Selects `ViewpointDefinition`, `ViewDefinition`, `RenderingDefinition`, and
`ViewUsage` symbols.
Output structure is controlled by `script/templates/viewpoints.hbs`.

[source,scheme]
----
(define puml (generate-viewpoints-diagram (syster/file-symbols model)))
----

Accepts `"title"` and `"theme"` options.

== File output

=== `(write-plantuml-file text path)` → void

Write `text` (a PlantUML source string) to `path`,
creating or overwriting the file.

[source,scheme]
----
(write-plantuml-file (generate-bdd symbols) "out/vehicle-bdd.puml")
----

== Rendering

=== `(render-diagram puml-path format)` → void

Invoke `plantuml` to render `puml-path`.
`format` is a string: `"svg"`, `"png"`, `"pdf"`, or `"txt"`.
Output is written next to the `.puml` file.

[source,scheme]
----
(render-diagram "out/vehicle-bdd.puml" "svg")
----

=== `(render-diagram-to puml-path format output-dir)` → void

Render `puml-path` and write the output to `output-dir`.

[source,scheme]
----
(render-diagram-to "vehicle-bdd.puml" "svg" "docs/images")
----

=== `(render-and-open puml-path format)` → void

Render the diagram and open the result in the system default viewer.
Uses `xdg-open` on Linux.

== Utilities

=== `(symbol->class-block sym)` → string

Render a single `HirSymbol` as a PlantUML class block with `<<block>>` stereotype.
Used internally by `generate-bdd`; useful for custom generators.

[source,scheme]
----
(displayln (symbol->class-block (syster/find-by-name symbols "Engine")))
----

Output:

[source,text]
----
class "Engine" <<block>> {
  + power : Real
  ~ fuelIn
  ~ driveOut
}
----

=== `(composition-line parent-name part-sym)` → string

Return the PlantUML composition line for a part usage.

[source,scheme]
----
(composition-line "VehicleSystem" part-usage-sym)
; => "\"VehicleSystem\" *-- \"Engine\" : engine\n"
----

=== `(inheritance-line child-sym)` → string or `#f`

Return the PlantUML inheritance line for a symbol with a `Specializes`
relationship, or `#f` if none.

=== `(plantuml-header [title] [theme])` → string

Return the `@startuml … skinparam …` preamble.

=== `(plantuml-footer)` → string

Return `"@enduml\n"`.
