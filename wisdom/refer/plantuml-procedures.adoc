= PlantUML generation procedures reference
:description: Complete reference for the plantuml.scm Steel library and its sub-libraries
:icons: font

The `steel/` directory contains a suite of Steel Scheme libraries for generating
PlantUML diagrams from SysML v2 models.
The entry point is `plantuml.scm`, which loads all sub-libraries and exposes a
unified API.

[source,scheme]
----
(require "plantuml.scm")          ; with -L steel on the load path
; or
(require "steel/plantuml.scm")   ; from the project root
----

The `syster/base` functions (`syster/parse-file`, `hir-symbol/*`, etc.) and the
`hbs/*` functions are registered automatically by the Rust host — no `require`
is needed for them.

On load, `plantuml.scm` creates a shared Handlebars registry `*hbs*` and
registers ten templates from `*templates-dir*` (default: `"steel/templates"`).
All diagram generators call `(hbs/render *hbs* ...)` internally.

All procedures that generate diagrams accept an optional `opts` hash as their
last argument.  Omitting it uses the defaults shown in the tables below.

See xref:library-structure.adoc[Steel library structure] for details on loading
individual sub-libraries independently.

== Structural diagrams

=== `(generate-bdd symbols [opts])` → string

Generate a Block Definition Diagram from a flat list of `HirSymbol` values.

Selects `PartDefinition`, `ItemDefinition`, `AttributeDefinition`,
`PortDefinition`, `ConnectionDefinition`, `ActionDefinition`,
`StateDefinition`, `RequirementDefinition`, and `EnumerationDefinition`
symbols.
Renders each definition as a PlantUML `class` with the `<<block>>` stereotype.
Derives composition lines from `PartUsage` children typed by another definition.
Derives inheritance lines from `Specializes` relationships.

Corresponds to `VCompartment` / `VTree` in the Java pilot implementation.

[source,scheme]
----
(define puml-text (generate-bdd (syster/file-symbols model)))
----

[cols="2,1,1,3"]
|===
| Key | Type | Default | Effect

| `"title"` | string | `""` | Add a `title` directive
| `"theme"` | string | `"plain"` | PlantUML `!theme` directive
|===

Output structure is controlled by `steel/templates/bdd.hbs`.

=== `(generate-ibd parent-sym symbols [opts])` → string

Generate an Internal Block Diagram showing the interior of `parent-sym`.

Selects `PartUsage` and `PortUsage` children of `parent-sym`, filtering out
unnamed internal elements.
Renders each part as a labelled component with a PlantUML-safe alias.

Corresponds to `VComposite` in the Java pilot implementation.

[source,scheme]
----
(define vs   (syster/find-by-name symbols "VehicleSystem"))
(define puml (generate-ibd vs symbols))
----

[cols="2,1,1,3"]
|===
| Key | Type | Default | Effect

| `"title"` | string | `""` | Diagram title
| `"direction"` | string | `"left to right direction"` | Diagram layout direction
|===

Output structure is controlled by `steel/templates/ibd.hbs`.

=== `(generate-package-diagram symbols [opts])` → string

Generate a package diagram showing packages and their contents.

Selects `Package` symbols and their direct children, merging packages that share
a name (which occurs when multiple source files declare the same package).

[source,scheme]
----
(define puml (generate-package-diagram (syster/file-symbols model)))
----

Accepts `"title"` and `"theme"` options.
Output structure is controlled by `steel/templates/package.hbs`.

=== `(generate-viewpoints-diagram symbols [opts])` → string

Generate a diagram showing viewpoints, view definitions, renderings, and their
instantiation and rendering relationships.

Selects `ViewpointDefinition`, `ViewDefinition`, `RenderingDefinition`, and
`ViewUsage` symbols.

[source,scheme]
----
(define puml (generate-viewpoints-diagram (syster/file-symbols model)))
----

Accepts `"title"` and `"theme"` options.
Output structure is controlled by `steel/templates/viewpoints.hbs`.

== Behavioral diagrams

=== `(generate-state-machine sym symbols [opts])` → string

Generate a state machine diagram for a `StateDefinition` symbol.

Selects `StateUsage` and `TransitionUsage` children of `sym`.
Transitions are rendered as `-->` arrows labelled with the transition name.

Corresponds to `VStateMachine` + `VStateMembers` in the Java pilot
implementation.

[source,scheme]
----
(define op-state (syster/find-by-name symbols "OperationalState"))
(define puml     (generate-state-machine op-state symbols))
----

Accepts a `"title"` option; the title defaults to `"<name> State Machine"`.
Output structure is controlled by `steel/templates/state-machine.hbs`.

=== `(generate-action-flow sym symbols [opts])` → string

Generate an action flow diagram for an `ActionDefinition` symbol.

Selects `ActionUsage`, `PerformActionUsage`, `SendActionUsage`, and
`AcceptActionUsage` children as nodes.
Selects `TransitionUsage` children as directed edges, rendered as `..>` arrows
(matching `VAction`'s dotted succession style from the Java pilot).

Corresponds to `VAction` + `VActionMembers` in the Java pilot implementation.

[source,scheme]
----
(define mission (syster/find-by-name symbols "ScoutMission"))
(define puml    (generate-action-flow mission symbols))
----

Accepts `"title"` (defaults to `"<name> Action Flow"`) and `"theme"` options.
Output structure is controlled by `steel/templates/action-flow.hbs`.

=== `(generate-action-flow-all symbols [opts])` → list of `(name . puml-string)` pairs

Generate action flow diagrams for every `ActionDefinition` that has
`ActionUsage` children.  Returns a list of pairs for batch processing.

[source,scheme]
----
(for-each
  (lambda (pair)
    (write-plantuml-file (cdr pair)
                         (string-append "out/" (car pair) ".puml")))
  (generate-action-flow-all symbols))
----

== Requirement diagrams

=== `(generate-requirement-diagram symbols [opts])` → string

Generate a requirement diagram from a flat list of `HirSymbol` values.

Selects `RequirementDefinition` and `RequirementUsage` symbols.
Renders each as a labelled rectangle with the `<<requirement>>` or
`<<requirementDef>>` stereotype.

Relationship kinds recognised in `hir-symbol/relationships`:

[cols="1,3"]
|===
| Relationship kind | PlantUML line

| `DeriveReqt`  | `source <.. target : <<deriveReqt>>`
| `Satisfy`     | `satisfier ..\|> requirement : <<satisfy>>`
| `Refine`      | `source ..> target : <<refine>>`
| `Specializes` | containment: `parent *-- child`
|===

Corresponds to `VRequirement` + `VCompartment` in the Java pilot implementation.

[source,scheme]
----
(define puml (generate-requirement-diagram (syster/file-symbols model)))
----

Accepts `"title"` (defaults to `"Requirement Diagram"`) and `"theme"` options.
Output structure is controlled by `steel/templates/requirement.hbs`.

=== `(generate-requirement-diagram-scoped sym all-symbols [opts])` → string

Generate a requirement diagram scoped to the `RequirementDefinition` /
`RequirementUsage` children of `sym`.

[source,scheme]
----
(define sys (syster/find-by-name symbols "SystemRequirements"))
(define puml (generate-requirement-diagram-scoped sys symbols))
----

== Interaction diagrams

=== `(generate-sequence-diagram sym all-symbols [opts])` → string

Generate a sequence diagram for an interaction context `sym`.

Selects `PartUsage`, `ItemUsage`, and `OccurrenceUsage` children as
participants (lifelines).
Selects `ConnectionUsage`, `FlowUsage`, and `MessageUsage` children as
messages; endpoint names are derived from connector-end children.

NOTE: The Java `VSequence` implementation derives message ordering from
`Succession` relationships and feature chains. This Scheme implementation
emits messages in declaration order.  Succession-based ordering is a planned
improvement.

[source,scheme]
----
(define interaction (syster/find-by-name symbols "SensorQueryInteraction"))
(define puml        (generate-sequence-diagram interaction symbols))
----

Accepts `"title"` (defaults to `"<name> Sequence"`) and `"theme"` options.
Output structure is controlled by `steel/templates/sequence.hbs`.

=== `(generate-use-case-diagram symbols [opts])` → string

Generate a use case diagram from a flat list of `HirSymbol` values.

Selects `UseCaseDefinition`, `UseCaseUsage`, `CaseDefinition`, and
`CaseUsage` symbols as use cases.
Selects `ActorUsage` and `ActorDefinition` symbols as actors.
Derives actor→use-case edges from `References` relationships.
Derives include edges from `Specializes` relationships between use cases.

Corresponds to `VCase` + `VCaseMembers` in the Java pilot implementation.

[source,scheme]
----
(define puml (generate-use-case-diagram (syster/file-symbols model)
               (hash "title"       "Campaign Use Cases"
                     "system_name" "Campaign System")))
----

[cols="2,1,1,3"]
|===
| Key | Type | Default | Effect

| `"title"` | string | `"Use Case Diagram"` | Diagram title
| `"theme"` | string | `"plain"` | PlantUML `!theme` directive
| `"system_name"` | string | `"System"` | Label on the system boundary rectangle
|===

Output structure is controlled by `steel/templates/use-case.hbs`.

== File output

=== `(write-plantuml-file text path)` → void

Write `text` (a PlantUML source string) to `path`,
creating or overwriting the file.

[source,scheme]
----
(write-plantuml-file (generate-bdd symbols) "out/vehicle-bdd.puml")
----

== Rendering

=== `(render-diagram puml-path format)` → void

Invoke `plantuml` to render `puml-path`.
`format` is a string: `"svg"`, `"png"`, `"pdf"`, or `"txt"`.
Output is written next to the `.puml` file.
Runs `plantuml` with `-Djava.awt.headless=true` so no display is required.

[source,scheme]
----
(render-diagram "out/vehicle-bdd.puml" "svg")
----

=== `(render-diagram-to puml-path format output-dir)` → void

Render `puml-path` and write the output to `output-dir`.

[source,scheme]
----
(render-diagram-to "vehicle-bdd.puml" "svg" "docs/images")
----

=== `(render-and-open puml-path format)` → void

Render the diagram and open the result in the system default viewer.
Uses `xdg-open` on Linux.

== Shared utilities (from `sysml-util.scm`)

These are re-exported by `plantuml.scm` and available to any script that
loads it.

=== `(pu-alias name)` → string

Return a PlantUML-safe identifier by replacing characters outside `[A-Za-z0-9_]`
with `_`.

=== `(filter-kind symbols kind-str)` → list

Return symbols whose `hir-symbol/kind` equals `kind-str`.

=== `(filter-kinds symbols kind-list)` → list

Return symbols whose `hir-symbol/kind` is a member of `kind-list`.

=== `(filter-map f lst)` → list

Map `f` over `lst`, dropping `#f` results.

=== `(find-syster-by-name symbols name)` → symbol or `#f`

Return the first symbol in `symbols` whose name equals `name`, or `#f`.

=== `(find-rel rels kind)` → relationship or `#f`

Return the first relationship in `rels` whose kind equals `kind`, or `#f`.

=== `(find-rels rels kind)` → list

Return all relationships in `rels` whose kind equals `kind`.

=== `(rel-targets sym kind)` → list of strings

Return the target name strings of all relationships of `kind` on `sym`.

[source,scheme]
----
(rel-targets vehicle-def "Specializes")
; => ("AbstractVehicle")
----

=== `(hash-try-get hash key)` → value or `#f`

Return `(hash-ref hash key)` if `key` is present, `#f` otherwise.
