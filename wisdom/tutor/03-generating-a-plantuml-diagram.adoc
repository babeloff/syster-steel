= Tutorial 3 — Generating a PlantUML diagram end-to-end
:description: From a SysML v2 model to a rendered SVG Block Definition Diagram
:icons: font

This tutorial takes you from a SysML v2 model file all the way to a rendered SVG
Block Definition Diagram (BDD),
using Steel scripts to drive the conversion.

*Prerequisites:* complete xref:02-loading-a-sysml-model.adoc[Tutorial 2].
No additional dependencies are required — SVG is rendered in-process via the
`layout/render-dot` Rust binding (backed by `layout-rs`).

The diagram below shows the full generation pipeline you will follow in this tutorial:

image::../diagrams-gen/pipeline-flow.svg[Diagram generation pipeline,width=600,align=center]

== 1. The model

Use `vehicle.sysml` from Tutorial 2 (`data/docs/vehicle.sysml`):

[source,sysml]
----
include::../../data/docs/vehicle.sysml[]
----

== 2. Write the generation script

The script `steel/gen-bdd.scm` implements the pipeline end-to-end:

[source,scheme]
----
include::../../steel/gen-bdd.scm[]
----

== 3. Run the script

----
syster-steel steel/gen-bdd.scm
----

[source,scheme]
----
;;; ── main ─────────────────────────────────────────────────────────────────
(generate-bdd "vehicle.sysml" "vehicle-bdd.puml")
----

Output:

----
Wrote vehicle-bdd.puml
----

Inspect the generated file:

----
cat vehicle-bdd.puml
----

[source,text]
----
@startuml
skinparam classBackgroundColor<<block>> LightSteelBlue

class "VehicleSystem" <<block>> {
  + mass : Real
  ~ drivePort
}

class "Engine" <<block>> {
  + power : Real
  ~ fuelIn
  ~ driveOut
}

class "Chassis" <<block>> {
  + weight : Real
}

"VehicleSystem" *-- "Engine" : engine
"VehicleSystem" *-- "Chassis" : chassis

@enduml
----

== 4. Render to SVG

SVG rendering happens automatically as part of diagram generation — no separate
step is needed.  The `dot.scm` library generates a DOT-language graph from the
same symbol data, and the `layout/render-dot` Rust binding (backed by
`layout-rs`, using the Sugiyama hierarchical layout algorithm) converts it to SVG
entirely in-process.

When you ran the script in Step 3, `vehicle-bdd.svg` was written alongside
`vehicle-bdd.puml`.  Open it in any browser or SVG viewer.

The `.puml` file is also written for reference.
If you have plantuml installed separately, you can render it manually:

----
plantuml -svg vehicle-bdd.puml
----

or to PNG:

----
plantuml -png vehicle-bdd.puml
----

plantuml is *not* a required dependency; the `.svg` produced by `layout-rs` is
the primary output.
