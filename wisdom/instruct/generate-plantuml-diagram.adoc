= How to generate a PlantUML diagram from a SysML v2 model
:description: Generating BDD, IBD, package, and state machine diagrams from Steel scripts
:icons: font

Require the plantuml library at the top of your script.
The `syster/base` and `hbs/*` functions are registered automatically — no require
needed for them.

[source,scheme]
----
(require "plantuml")          ; from script/plantuml.scm — run with -L script
----

`plantuml.scm` loads Handlebars templates from `script/templates/` on startup.
Run scripts from the project root so the path resolves correctly, or set
`*templates-dir*` before the first `require`:

[source,scheme]
----
(define *templates-dir* "path/to/templates")
(require "plantuml")
----

== Block Definition Diagram (BDD)

A BDD shows block definitions, their attributes, ports, and composition relationships.
It corresponds to a SysML v2 Part Definition tree.

[source,scheme]
----
(define model   (syster/parse-file "vehicle.sysml"))
(define symbols (syster/file-symbols model))

(write-plantuml-file
  (generate-bdd symbols)
  "vehicle-bdd.puml")
----

To filter to a specific package:

[source,scheme]
----
(define pkg-syms
  (filter (lambda (s)
            (starts-with? (hir-symbol/qualified-name s) "VehicleModel::"))
          symbols))

(write-plantuml-file (generate-bdd pkg-syms) "vehicle-bdd.puml")
----

== Internal Block Diagram (IBD)

An IBD shows the internal structure of one block:
its part usages and port connections.

[source,scheme]
----
(define vs (syster/find-by-name symbols "VehicleSystem"))

(write-plantuml-file
  (generate-ibd vs symbols)
  "vehicle-ibd.puml")
----

== State Machine Diagram

Shows state definitions and transitions within an action or state definition.

[source,scheme]
----
(define state-def (syster/find-by-name symbols "OperationalState"))

(write-plantuml-file
  (generate-state-machine state-def symbols)
  "operational-state.puml")
----

== Dependency / package diagram

Shows packages and their import relationships.

[source,scheme]
----
(write-plantuml-file
  (generate-package-diagram symbols)
  "packages.puml")
----

== Customise the output

All generators accept an optional options hash as their last argument:

[source,scheme]
----
(write-plantuml-file
  (generate-bdd symbols
    (hash "theme" "plain"
          "title" "Vehicle System BDD"))
  "vehicle-bdd.puml")
----

[cols="2,1,1,3"]
|===
| Option key | Type | Default | Effect

| `"title"` | string | `""` | Add a `title` directive
| `"theme"` | string | `"default"` | PlantUML `!theme` directive
| `"direction"` | string | `"left to right direction"` | IBD layout direction (IBD only)
|===

== Customise the templates

The PlantUML structure is defined by Handlebars templates in `script/templates/`.
To change how diagrams look — adding `skinparam` directives, reformatting class boxes,
switching relationship notation — edit the relevant `.hbs` file directly.

To use a parallel set of templates without modifying the originals, copy the
`script/templates/` directory and point `*templates-dir*` at the copy before requiring
`plantuml`.

See xref:../refer/hbs-bindings.adoc[Handlebars Steel bindings reference] for the full
`hbs/*` API, including how to register additional templates into the shared `*hbs*`
registry.

== Write to a specific directory

[source,scheme]
----
(require-builtin steel/filesystem)

(create-directory! "out")
(write-plantuml-file (generate-bdd symbols) "out/vehicle-bdd.puml")
----
