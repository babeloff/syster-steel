= syster-steel
:description: Steel Scheme REPL and script runner for SysML v2 workflows
:toc: left
:toclevels: 2
:icons: font

syster-steel embeds the https://mattwparas.github.io/steel/book/[Steel Scheme]
interpreter as a command-line tool for the
https://github.com/jade-codes/syster-base[syster] SysML v2 toolchain.
It provides an interactive REPL and a script runner,
both backed by a single `steel-core` `Engine` instance.

Steel scripts can load and query parsed SysML v2 models,
generate PlantUML diagrams,
and drive any other transformation or reporting task —
without recompiling the toolchain.

== Quick start

=== Install

Install `syster-steel` globally with https://pixi.sh[pixi] from the
https://prefix.dev/channels/meso-forge[meso-forge] channel:

[source,shell]
----
pixi global install --channel conda-forge --channel https://prefix.dev/meso-forge syster-steel
----

Verify the installation:

[source,shell]
----
syster-steel --version
----

=== Use

[source,shell]
----
# Start the interactive REPL
syster-steel

# Run a script
syster-steel -L script script/gen-plantuml.scm

# Run a script, then stay in the REPL
syster-steel -i -L script script/gen-plantuml.scm

# Evaluate an inline expression
syster-steel -e "(displayln (+ 1 2))"
----

See link:wisdom/refer/cli.adoc[CLI reference] for the full flag listing.

== Building

With https://pixi.sh[pixi] (recommended):

[source,shell]
----
pixi run build     # debug build
pixi run test      # run the test suite
pixi run check     # lint with Clippy
pixi run repl      # start the REPL via cargo run
pixi run package   # build conda packages into output/
pixi run publish   # build and upload to prefix.dev/meso-forge
----

`pixi run publish` requires a `PREFIX_API_KEY` environment variable with a
valid https://prefix.dev[prefix.dev] API key.

With cargo directly:

[source,shell]
----
cargo build --release
----

== Architecture

syster-steel is a concrete example of
https://mattwparas.github.io/steel/book/start/embedded.html[using Steel as an embedded scripting engine].
The `steel-core` crate provides the VM;
this application creates an `Engine`,
registers syster-base types and accessor functions,
then hands control to user-supplied Scheme scripts.

----
syster-base (Rust library)
    │  parses SysML v2 → HirSymbol list
    ▼
syster-steel (this crate)
    │  registers HirSymbol accessors — src/bridge.rs
    │  registers hbs/* template API  — src/hbs.rs
    │  runs scripts via Engine::run
    ▼
Steel Scheme scripts (script/)
    │  filter symbols → data hash → hbs/render
    ▼
Handlebars templates (script/templates/)
    │  render PlantUML source
    ▼
plantuml → SVG / PNG / PDF
----

See link:wisdom/explain/steel-as-extension-language.adoc[Why Steel Scheme as the extension language]
for a full explanation.

== Project layout

----
syster-steel/
├── src/
│   ├── main.rs        — entry point; creates Engine, registers bindings, runs scripts
│   ├── bridge.rs      — registers syster-base types and accessors with the Engine
│   ├── hbs.rs         — registers hbs/* Handlebars bindings with the Engine
│   ├── cli.rs         — clap argument definitions
│   └── repl.rs        — rustyline REPL with multi-line input and history
├── script/
│   ├── plantuml.scm   — Steel library for generating PlantUML diagrams
│   ├── gen-plantuml.scm — generates all diagrams from data/campaign/
│   ├── gen-bdd.scm    — standalone BDD generation tutorial script
│   ├── templates/     — Handlebars templates for each PlantUML diagram type
│   └── examples/      — tutorial example scripts
├── data/
│   ├── campaign/      — SysML v2 campaign model (multi-file)
│   └── docs/          — SysML v2 example models used in tutorials
├── wisdom/
│   ├── tutor/         — step-by-step tutorials
│   ├── instruct/      — how-to guides
│   ├── explain/       — explanations and design rationale
│   └── refer/         — reference docs
├── Cargo.toml
├── pixi.toml          — build tasks and conda environment
├── recipe.yaml        — rattler-build conda package recipe
└── LICENSE
----
